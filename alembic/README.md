# `alembic/` — the schema

18 migrations, `0001` → `0018`. The application **refuses to start** if the database is not
at the expected revision. It checks `EXPECTED_REVISION` in
[`revora/persistence/repositories/schema.py`](../revora/persistence/repositories/schema.py) at
startup, so a half-migrated deployment fails loudly instead of failing on its first write.

**Deep dive:** [`references/REVORA-SYSTEM-GUIDE.md`](../references/REVORA-SYSTEM-GUIDE.md) and the
Data Models section of each [spec's design doc](../.kiro/specs/).

---

## Running them

```powershell
. .\scripts\dev_env.ps1                            # sets the DSN and local secrets
.venv\Scripts\python.exe -m alembic upgrade head
.venv\Scripts\python.exe -m alembic current        # confirm 0018
```

For a managed database, first set `REVORA_DATABASE_URL` to its DSN (connection string).

> **Deploying?** Migrate **before** the new image goes live, or the API's startup check rejects it.

## The migrations

| # | Name | What it does |
| --- | --- | --- |
| 0001 | `initial_schema` | Every core table, every `CHECK`, every money column as `BIGINT` |
| 0002 | `audit_append_only` | Removes `UPDATE`/`DELETE` rights on `audit_record` and adds the trigger. Any attempt to change a row is itself logged |
| 0003 | `row_level_security` | RLS + a `tenant_isolation` policy on every tenant-scoped table |
| 0004 | `seed_configuration` | The configuration bounds, as rows — not code constants |
| 0005 | `evidence_tables` | Experiment, memory and metrics tables |
| 0006 | `dashboard_sessions` | `merchant_session`, so sessions are revocable |
| 0007 | `widen_duration_columns` | Durations to `bigint` |
| **0008** | `customer_response_loop` | The four customer tables, `next_review_at`, `effect_kind`, the four-term cost split |
| 0009 | `seed_cost_split_bounds` | Cost-split bounds, generated from the code catalogue so the two cannot drift apart |
| 0010 | `seed_review_loop_bounds` | `WAIT_REVIEW_INTERVAL`, `REVIEW_SWEEP_INTERVAL` |
| 0011 | `seed_customer_token_bounds` | Token lifetime and submission caps |
| 0012 | `seed_customer_surface_bounds` | The public page's two rate limits and two caps |
| 0013 | `seed_customer_stated_cause_bound` | `CUSTOMER_STATED_CAUSE_CONFIDENCE` |
| 0014 | `seed_sweep_interval_bounds` | The three ticker intervals |
| 0015 | `widen_terminal_reason_enum` | The four customer-stated endings. **Before this, the `CHECK` made them impossible to store** |
| 0016 | `seed_promise_bounds` | The five `Promise_To_Pay` bounds |
| 0017 | `widen_exclusion_reason_enum` | Two promise grounds |
| 0018 | `widen_exclusion_reason_live_link` | `LIVE_PAYMENT_LINK_EXISTS` — fixed a real bug that allowed two payable links at once |

Eleven of the eighteen are **data-only seeds.** That is on purpose: a configurable bound lives in
`app_config` as a versioned row, so changing it is a config change, not a code deploy. See
*Configuration* in the root README.

## Conventions

- **Every money column is `BIGINT`** via the `MONEY` alias. Integer minor units, everywhere.
- **Every enumeration is `TEXT` with a `CHECK`** generated by `enum_check` from the Python enum, so
  the database and the code cannot drift apart. Adding an enum member therefore needs a migration —
  and that is the point. It is the moment somebody should notice that a new terminal state has no test.
- **Seed migrations generate their rows from the code catalogue**, so the accessor and the table
  cannot disagree.
- Migration `0003` built its RLS table list from the metadata *as it stood then*, so **any table
  added later must create its own policy.** `0008` does.

## Downgrades refuse rather than destroy

`0008`'s downgrade checks three things first and stops if any of them are true:

1. A **live contact suppression** exists. Dropping it would quietly allow contact again with a
   customer who disputed a charge. This is the one harm in the migration that cannot be undone.
2. A case is `POLICY_CHECK` with a `next_review_at`. Nothing else re-decides it, so dropping the
   column would leave it stuck out of sight until its window runs out.
3. A `PAYMENT_LINK_RESEND` intent is `UNCERTAIN`. Restoring the old index predicate would make the
   sweep start issuing reads for effects that cannot be read.
