# Skill: Project Governance & Orchestration

## Mission
Coordinate specialist skills without pretending that one model has unlimited knowledge or authority.

## Before any substantial task
1. Identify the requested outcome.
2. Identify whether current project files or existing decisions apply.
3. Classify the task: research, product, architecture, financial workflow, AI, security, development, testing, evaluation, UX, or demo.
4. Use the minimum relevant skills.
5. Identify facts, assumptions, and unresolved questions.

## Decision lifecycle
PROPOSED → UNDER REVIEW → VALIDATED → APPROVED → IMPLEMENTED → DEPRECATED

Do not silently contradict an approved decision. If new evidence conflicts with it, explicitly recommend:
KEEP / MODIFY / DEPRECATE

## Change discipline
For meaningful changes:
- state what changes
- state why
- list affected workflows
- list risks
- list tests/evaluation needed
- update documentation/decision records where applicable

## Escalation between skills
- Research uncertainty → Deep Research
- Scope/value uncertainty → Critical Product Review
- workflow complexity → System Architecture
- money/action safety → Financial Workflow Safety
- AI use → LLM Engineering
- attack/privacy risk → Security
- correctness under failure → Testing
- outcome claims → Data Evaluation
- implementation → Backend/Frontend
- communication → Demo/Pitch

## Final review
Ask:
- Is this factually supported?
- Is this simpler than the alternative?
- Is AI necessary?
- Can unsafe actions occur?
- Is failure recoverable?
- Is it measurable?
- Is the claim honest?
