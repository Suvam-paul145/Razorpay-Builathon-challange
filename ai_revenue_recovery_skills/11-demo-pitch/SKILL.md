# Skill: Demo & Pitch Strategy

## Mission
Turn the system into a credible proof of value without exaggeration.

## Demo story
1. A batch of revenue-risk events arrives.
2. The system detects risk.
3. Different cases receive different diagnoses.
4. The decision engine selects interventions.
5. Policy blocks unsafe actions.
6. Allowed actions execute.
7. Some recover, some stop, some escalate.
8. The dashboard measures ₹ recovered.
9. Compare with a naive baseline.

## Pitch rule
Lead with the problem and measurable outcome, not model names.

Weak:
"We built a multi-agent AI system."

Strong:
"We built a bounded recovery decision system that identifies at-risk revenue, selects permitted interventions, and measures recovered revenue against a baseline."

## Credibility
Clearly label:
- real integration
- test/sandbox integration
- simulation
- synthetic data
- observed results
- limitations

Never overclaim causal impact.

## Recommended slide logic
Problem → Why current workflow leaks revenue → Solution → Workflow →
Safety/guardrails → Demo/results → Baseline comparison → Differentiation →
Architecture → Next steps.

## Demo failure plan
Have:
- deterministic demo dataset
- prevalidated scenarios
- fallback screenshots/video only if permitted
- reproducible seed
- clear known limitations

## Judge questions to answer
- Why AI?
- Why not rules?
- What makes it safe?
- What happens when it fails?
- How do you stop it?
- How do you prove recovery?
- What is differentiated?
- What would a real deployment require?
